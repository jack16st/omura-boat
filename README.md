# ボートレースAI予測・資金配分アプリ

## 実行方法
```bash
pip install streamlit pandas beautifulsoup4 curl_cffi
streamlit run app.py
```

## v3での変更点（DB保存）
- 出走表・直前情報は`history.py`（SQLite, `history.db`）に保存し、同じレースを再度開いたときは
  サイトへ再アクセスせず保存済みデータを使う
- オッズは締切前は変動し続けるため、締切通過も確定結果もまだの間は毎回最新を取得する
- **締切予定時刻を直前情報ページから抽出し、締切通過後はオッズを固定値としてロックして以後は再取得しない**
  （`odds_locked`フラグ）。確定結果が出た場合も同様にロックする
- 確定結果は一度取得できたらDBに保存し、以後は再取得しない
- サイドバーに「出走表・直前情報も強制的に再取得する」チェックボックスを追加（差し替え等の例外時用）
- 画面上部に状態表示（保存済みデータ使用中／締切通過／結果確定済み）を追加

### 締切判定の注意
締切予定時刻は`beforeinfo`ページのテキストから正規表現で抽出している（`締切予定 18:20`のような
表記を想定）。ページの表記が異なる場合は取得できずNoneのままになり、その場合は締切通過の判定は
できないため、確定結果が出るまでオッズは毎回取得され続ける（安全側に倒れる動作）。

### 永続化の注意
`history.db`はアプリと同じディレクトリに作られるSQLiteファイル。Streamlit Community Cloudなど
一時的なファイルシステムの環境では、再デプロイ・長期間の休止でファイルごと消える可能性がある。
稼働中は保存され続けるが、長期保存を厳密に保証したい場合は外部DB
（Supabase / PostgreSQL、Google Sheets等）への切り替えを検討すること。

## v2での変更点
- トップ画面に「本日の締切間近レース Top5」を追加（`scraper.fetch_upcoming_deadlines`）
- 券種選択に「おすすめ」を追加（常に3連単ベースで予測・資金配分を算出）。デフォルトは券種・予算とも「おすすめ」
- 予算は「おすすめ（1000円）」か「カスタム」を選択
- ①予測・スコア: おすすめフォーメーション(必須)→カスタムフォーメーション(券種指定時)→スコア簡易表→展開予測→全舟診断
- ②詳細データ: 出走表詳細→気象情報→リアルタイムオッズ(3連単・全件)
- ③資金配分・結果: 結果判明時は先頭に的中/ハズレ表示→おすすめ資金配分(必須)→カスタム資金配分(券種指定時)。各配分は合成オッズのみ表示（合計投資額表示は削除）

### Top5機能の注意
`/race/raceindex` は robots.txt でアクセス不可のため、全会場の状況が一覧できる `/race/index`
（本日のレース）を使っている。ただし検証時点ではその日の全レースが終了しており、
「稼働中レースの締切表示」の実際のテキストパターン（何R・何時何分の表記ゆれ）は
確認できていない。`scraper.fetch_upcoming_deadlines` 内の正規表現は推測ベースなので、
本番運用前に稼働中の時間帯で動作確認すること。

## ファイル構成
- `constants.py` — 会場コード、券種、コース基礎勝率などの定数
- `parsing_utils.py` — rowspan/colspanを展開するテーブル解析共通処理
- `scraper.py` — ①boatrace.jpスクレイピング（出走表・直前情報・オッズ・確定結果）
- `scorer.py` — ②AIスコアリング・推奨フォーメーション選定
- `allocator.py` — ③資金配分（トリガミ防止・利益均等化）
- `settlement.py` — ④収支自動集計・的中判定
- `app.py` — Streamlit UI（①〜④を統合）
- `test_offline.py` — ネットワーク不要な範囲のオフライン検証テスト

## 検証状況（重要）
このサンドボックス環境はネットワークアクセスができないため、`curl_cffi` によるboatrace.jp
への実アクセスはテストできていません。代わりに以下を実施済みです。

- `web_fetch` で実際の以下4ページを取得し、列構成・データ構造を確認済み:
  出走表(racelist)、直前情報(beforeinfo)、3連単オッズ(odds3t)、確定結果(raceresult)
- 上記で確認した列構成を模したHTML断片を使い、`test_offline.py` でパーサ・スコアリング・
  資金配分・収支判定の各ロジックをオフライン検証済み（`python3 test_offline.py` で全件PASS）

### 未検証・要確認の項目
- 実際のHTMLのrowspan/colspanの入り方が、確認した表示内容から推測した構造と完全に一致するか
  （`scraper.py` の出走表・直前情報・3連単オッズパーサ）
- 2連単・2連複 / 拡連複 / 単勝・複勝 のオッズページ構造は未取得のため `_parse_matrix_odds` /
  `_parse_single_odds` は暫定実装（`scraper.py`内に要調整の旨コメント記載）
- 実際のリクエスト頻度に対するサイト側のブロック挙動（`curl_cffi` の `impersonate="chrome110"`
  で回避できるかどうか）

初回はネットワーク接続がある環境で `streamlit run app.py` を実行し、①予測・スコアタブに
実データが表示されるか確認してください。パースに失敗した場合はアプリ画面にエラー内容が
表示され、自動的にモックデータへフォールバックします。
